Part 1 Prompt 工程设计

四种 Prompt，各司其职
1 提取：从论文 Markdown 中找出定理声明，区分「作者提出」与「引用前人」
2 分类：为每个定理分配关键词标签与领域分类（30+ 预定义标签）
3 摘要：以通俗中文解释定理核心含义，控制在三句话以内
4 关系：判断两定理之间为推导、推广、等价或依赖关系
关键经验：Prompt 需明确约束条件与结构化输出格式，具体程度决定输出质量。

Part 2 论文问答智能体：从图谱到对话

上传论文，自动构建知识图谱
将 PDF / Markdown 论文放入论文池，系统自动扫描、提取定理、构建知识图谱
自然语言问答，图谱实时联动
以中文提问，系统检索图谱中相关定理，LLM 综合推理后生成答案，同时高亮图谱中对应节点
AI 自动合并等价定义
不同论文中表述不同的等价定义，由 AI 识别并合并，避免知识碎片化
技术栈：FastAPI + Vue 3 + ECharts + LLM，纯 Python 后端，零构建前端

Part 2 问答流程：图谱检索增强生成

五步处理流程
1 用户输入自然语言问题
2 关键词提取，在知识图谱中检索相关定理
3 将定理内容作为 Context 注入 LLM Prompt
4 LLM 综合推理，返回 Markdown + KaTeX 渲染答案
5 同时高亮图谱中关联节点，实现可视化联动
设计思路：知识图谱提供结构化精准检索，LLM 提供自然语言理解与生成——两者互补，相较于纯向量检索的 RAG 方案更适合具有层级结构的知识。

Part 3 应用拓展：通用知识管理架构

同一架构，跨领域复用

法律文书检索：上传法规文档，提取条款与判例关联，支持自然语言法律咨询
课程知识体系：导入课件与教材，构建学科知识图谱，回答跨章节概念关联问题
